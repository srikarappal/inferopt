# Serving environment. Install into ONE venv and run everything with that
# interpreter -- the most common failure on a new host is running the CLI with a
# different python than the one vLLM lives in, which surfaces as
# `FileNotFoundError: 'vllm'` from deep inside a subprocess.
#
#   ./install_vllm.sh                                    # NOT plain pip
#   python -c "import vllm; print(vllm.__version__)"      # must succeed
#
# vLLM IS NOT LISTED HERE, and that is deliberate.
#
# `pip install vllm==0.26.0` resolves to the PyPI default wheel, which for 0.26
# is built against CUDA 13. On a host whose driver reports 12.x that wheel
# imports and then dies on `libcudart.so.13: cannot open shared object file` --
# and worse, it drags torch, torchvision, torchaudio and torchcodec in as CUDA 13
# builds too, so fixing them one at a time fails one import deeper each round.
#
# The right build depends on the DRIVER, which a requirements file cannot see.
# install_vllm.sh reads it from nvidia-smi and picks the matching wheel.
#
# vLLM stays version-pinned inside that script because it is the measurement
# instrument: 0.26 removed flags earlier versions accepted
# (--disable-log-requests, --swap-space, --cuda-graph-sizes,
# --tokenizer-pool-size) and renamed Prometheus metrics (gpu_cache_usage_perc ->
# kv_cache_usage_perc). Numbers from a different version are not comparable to
# the ones in docs/. A different CUDA BUILD of the same version is fine.

# torch is NOT pinned here on purpose. vLLM depends on it and the correct build
# is CUDA-version specific: cu126/cu128 for H100 (sm90), cu130 for GB10 (sm121).
# Let vLLM's own dependency resolution pick it, or install the matching wheel
# from pytorch.org FIRST if this host needs a specific CUDA. The reference
# environment for docs/ was torch 2.11.0+cu130.

transformers==5.14.1
datasets==5.0.1
huggingface-hub
httpx==0.28.1
pydantic==2.13.4
# Only validate_dag.py uses it, for graph properties any 3.x has.
# Pinned exactly, it made the install fail on Python 3.10, where 3.4.2
# is the last release -- a hard stop for a dev-only dependency.
networkx>=3.0
requests
certifi

# Only for docs/make_report.py, which regenerates the .docx from the result
# files. Not needed to run a ladder or a traversal.
python-docx==1.2.0

# NOT here, deliberately, and they must stay out of this environment:
#
#   evalplus        MBPP+ scoring. Drags in openai, anthropic and
#                   google-generativeai for ITS generation backends, which we do
#                   not use -- we generate with vLLM. setup.sh installs it into
#                   .evalplus-pkgs/ and mbpp_score.py reaches it via sys.path.
#
#   nvidia-modelopt Quantization producer, and the exception to the rule below.
#                   It has no pin conflicts with vLLM so it goes INTO the serving
#                   env, but it pulls setuptools 81 where vLLM requires <81, so
#                   the pin has to be reinstalled after it. setup.sh does both,
#                   in that order. Left out of this file because pip resolves a
#                   requirements file in one pass and cannot express "install
#                   this, then undo what it did to setuptools".
#
#   aiconfigurator  NVIDIA's config predictor, stage 1.2. Absent here because
#                   it declares numpy~=1.26.4 against this environment's 2.3.5,
#                   and pip has no way for a dependent to relax that. The pin is
#                   false: all five of its entry points give byte-identical
#                   output on numpy 2.3.5. setup.sh installs it with --no-deps
#                   until upstream fixes the metadata.
#
# This project has been broken twice by a dependency installed for a side
# feature. modelopt and aiconfigurator both go in with --no-deps; evalplus stays
# in its own directory.

# Plotting. compare.py --plot and plot_pb.py need matplotlib; without it they
# report "plot failed" and the run continues, which is the right behaviour for
# an optional output but a poor surprise at the end of a six-hour comparison.
# seaborn is not imported anywhere -- listed because it travels with these
# analyses in practice and costs nothing to have.
matplotlib>=3.7
seaborn
